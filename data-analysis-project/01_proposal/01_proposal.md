# 1. 프로젝트 제목

## KBO의 ‘운 없던 타자’는 다음 시즌 반등할까?

**개인별 BABIP 기준선과 다음 시즌 타율 회복의 관계 검증**

> 한 시즌의 낮은 타율만으로 타자를 평가해도 될까? 선수 본인의 과거 기록에 비해 안타로 연결된 타구가 적었던 시즌을 찾아, 이 정보가 다음 시즌 성적을 판단하는 데 도움이 되는지 확인한다.

# 2. 프로젝트 배경 및 목적

야구를 보면서 성적이 떨어진 선수에게 “실력이 줄었다”거나 “올해는 운이 없었다”는 평가가 붙는 것을 접했다. 그러나 한 시즌의 타율만으로 두 설명을 구분하기는 어렵다. 본 프로젝트는 KBO 타자를 대상으로, **개인의 평소 수준보다 낮은 BABIP를 기록한 시즌 이후 타율이 회복되는지** 분석한다.

BABIP는 홈런을 제외하고 경기장 안으로 들어간 타구가 안타가 된 비율이다. 계산식은 `(H - HR) / (AB - SO - HR + SF)`이다. 지표의 정의는 [MLB 공식 용어집](https://www.mlb.com/glossary/advanced-stats/babip)을 참고한다. 본 분석에서는 타구의 질, 주력, 상대 수비, 구장 등의 영향을 따로 측정할 수 없으므로, 낮은 BABIP를 순수한 ‘불운’으로 해석하지 않는다. 제목의 ‘운 없던 타자’는 검증할 통념을 나타내는 표현이다.

모든 선수에게 같은 BABIP 기준을 적용하면 선수마다 다른 타격 특성을 놓칠 수 있다. 따라서 **직전 3년의 개인 기록으로 기준선을 만들고, 시즌별 리그 환경 차이도 보정**한다. 또한 낮은 성적이 이후 자연스럽게 평균에 가까워지는 현상을 고려하여, 현재 타율과 과거 성적을 이미 반영한 분석에서도 BABIP 정보가 추가로 도움이 되는지 확인한다.

결과는 KBO 팬과 야구 콘텐츠 제작자가 한 시즌의 부진을 해석할 때 참고할 수 있다. 최종 결과물에서는 선수의 연도별 기록, 기준선 대비 차이, 과거 사례의 다음 시즌 변화를 함께 보여준다. 선수의 실제 기량 변화나 부진 원인을 확정하는 것이 아니라, **다음 시즌 성적과 관련된 관측 가능한 신호를 검증**하는 것이 목적이다.

## 4.2. 분석 범위와 예상 규모

분석 시점인 현재 시즌을 `t`, 다음 시즌을 `t+1`로 정의한다. **2015~2024년 시즌의 기록으로 2016~2025년 성적을 검증**한다. 개인 기준선 계산을 위해 2012~2014년을 포함한 과거 기록도 사용한다. 이 범위의 원본은 총 3,884행이다.

표본 조건은 다음과 같이 먼저 정한다.

1. 현재 시즌 `PA ≥ 200`, BABIP 분모인 `BIP = AB - SO - HR + SF ≥ 100`.
2. 직전 3개 연도 안에 양의 BIP를 가진 기록이 2시즌 이상 있고, 그 기간의 총 `BIP ≥ 300`.
3. 다음 시즌 타율을 평가하는 주 분석에서는 `t+1`에 `PA ≥ 200`인 기록을 사용한다.

이 조건을 확보한 CSV에 적용해 규모만 점검한 결과, 현재 시즌 조건을 충족하는 기록은 **758건**, 다음 시즌까지 평가 가능한 기록은 **597건·142명**이다. 최종 정제 과정에서 오류가 확인되면 표본 수는 달라질 수 있다. 신인이나 KBO 경력이 짧은 외국인 타자는 개인 기준선이 부족하여 주 분석에서 제외된다.

다음 시즌 기록이 없거나 타석이 부족한 **161건**은 실패·무반등으로 처리하지 않고 평가 제외 사유별로 집계한다. 결과의 적용 범위는 다음 시즌에도 일정 수준 이상 출전한 기존 타자이며, 은퇴·부상·출전 기회 감소까지 예측하는 프로젝트로 확대하지 않는다.

확보 점검의 재현 방법과 원본 해시는 [데이터 안내](../data/raw/README.md), 수치 요약은 [구조 점검 기록](../data/data_audit.json)에 남긴다.

## 4.3. 데이터 품질과 이용조건

배포 설명에 따르면 `SF`와 `SH`는 공개 출루율과 타석 관계식으로 복원한 추정치이며 반올림 등에 따른 오차가 있을 수 있다. 따라서 **SF를 공식 실측값으로 표시하지 않고**, 본 분석에서 SF를 ±1 변화시켰을 때 지표와 결론이 유지되는지 확인한다. 추정된 포지션·투타 정보는 주 분석 변수에서 제외한다. 참고용으로 구자욱의 2019~2025년 PA·AB·H·HR·BB·SO·AVG를 [KBO 통산기록](https://www.koreabaseball.com/Record/Player/HitterDetail/Total.aspx?playerId=62404)과 대조하여 일치함을 확인했으며, 이는 해당 선수의 일부 기본 기록에 한정된 점검이다.

Kaggle에 표시된 데이터 라이선스는 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/deed.ko)이다. 비상업적 수업 프로젝트로 이용하고, 배포자·출처·버전·라이선스·가공 내용을 명시한다. 데이터의 가공물을 공유할 때에는 동일한 라이선스 조건을 적용한다. 공개 저장소에는 원본 CSV를 재업로드하지 않고 출처, 다운로드 방법, 코드와 점검 요약을 제공한다. 이는 배포자가 표시한 라이선스이며 KBO의 공식 승인으로 표현하지 않는다.

[KBO 홈페이지 이용약관](https://www.koreabaseball.com/Etc/Policy.aspx)의 자동 수집 제한을 준수하며, 직접 대량 수집을 진행하지 않는다. 선수의 공개 경기 기록과 시즌 연령만 분석에 사용하고, 원본에 포함된 생년월일·신체정보·학력·지명 정보 등 불필요한 개인 정보는 분석 테이블에서 제거한다.

# 5. 예상 데이터 구조

최종 분석 테이블의 단위는 **타자 1명 × 현재 시즌 1개**이며, `Id`와 `Season`으로 연결한다. 동명이인은 이름이 아닌 ID로 구분한다.

| 원본 또는 파생 컬럼 | 의미 | 역할 |
|---|---|---|
| `Id`, `Player`, `Season`, `Team` | 선수 ID·이름·현재 시즌·소속 | 기록 연결 및 결과 표시. ID·이름은 예측 입력에서 제외 |
| `Age`, `PA`, `AB` | 시즌 연령·타석·타수 | 비교 조건, 표본 필터 |
| `H`, `HR`, `SO`, `BB`, `SF` | 안타·홈런·삼진·볼넷·복원 희생플라이 | 지표 계산 |
| `avg_t` | `H / AB`로 다시 계산한 현재 타율 | 현재 성적 |
| `bip_t`, `babip_t` | BABIP 분모와 현재 BABIP | 표본 크기·현재 타구 결과 |
| `league_babip_t` | 시즌 전체 타자의 합계로 계산한 리그 BABIP | 해당 시즌 리그 환경 |
| `baseline_babip_t` | 직전 3년의 개인 기록에 리그 환경을 반영한 기준선 | 개인별 비교 기준 |
| `babip_gap_t` | `baseline_babip_t - babip_t` | 핵심 설명 변수. 양수이면 기준보다 낮은 BABIP |
| `past_avg_t` | 직전 3년 총 안타 / 총 타수 | 과거 타격 수준 |
| `k_rate_t`, `bb_rate_t`, `hr_rate_t` | `SO / PA`, `BB / PA`, `HR / PA` | 현재 타격 결과의 다른 측면 |
| `avg_next`, `pa_next` | 다음 시즌 타율·타석 | 결과 및 평가 가능 여부. 예측 입력에서 제외 |
| `delta_avg` | `avg_next - avg_t` | 타율 회복 폭 |

개인 기준선은 시즌별 BABIP의 단순 평균 대신 **BIP를 가중치로 사용**한다. 각 과거 시즌의 개인 BABIP에서 그 시즌 리그 BABIP를 뺀 값의 가중평균을 구하고, 여기에 현재 시즌 리그 BABIP를 더한다.

```text
리그 BABIP_s = 전체 타자의 Σ(H_s - HR_s) / ΣBIP_s
개인 기준선_t = 리그 BABIP_t
              + Σ[BIP_s × (개인 BABIP_s - 리그 BABIP_s)] / ΣBIP_s
                (s는 t-3, t-2, t-1 중 이용 가능한 시즌)
BABIP 차이_t = 개인 기준선_t - 현재 BABIP_t
```

모든 입력 변수는 **현재 시즌 종료 시점까지 알려진 정보로만** 만든다. 이후 기록을 포함한 통산 BABIP나 다음 시즌의 리그 평균을 기준선에 넣지 않는다. 타율은 원본의 세 자리 반올림값 대신 안타·타수로 재계산한다.

# 6. 예상 분석 방법

## 6.1. 전처리와 탐색적 분석

- 숫자형 변환, ID–시즌 중복, 결측, `H ≤ AB`, `HR ≤ H`, BIP 분모와 기록 간 관계를 확인한다. 이적 선수의 기록이 시즌 합계인지도 점검한다.
- 시즌별 표본 수·탈락 비율과 타율·BABIP 분포를 확인한다. BABIP 차이의 분포, 타석 수·연령별 차이, 다음 시즌 변화의 산점도를 작성한다.
- Q2에서는 BABIP 차이를 연속 변수로 분석한다. 설명을 위한 그룹이 필요하면 학습 기간의 분위수로 경계를 정하고 이후 시즌에도 같은 경계를 사용한다.

## 6.2. 비교와 간단한 회귀분석

**‘BABIP가 낮았던 선수의 타율이 올랐다’는 단순 비교만으로 결론을 내리지 않는다.** 낮은 성적의 자연스러운 평균 회귀와 현재 타율을 공유하는 변화량끼리의 상관을 구분하기 위해, 다음 시즌 타율 자체를 종속 변수로 사용하고 현재 타율·과거 타율·연령·타석 수·삼진·볼넷·홈런 비율을 함께 고려한다. 회복 폭은 보조적으로 제시한다.

예측 검증은 작은 표본에 맞게 릿지 회귀를 우선 사용한다. 복잡한 딥러닝이나 여러 모델의 성능 경쟁은 프로젝트 범위에 포함하지 않는다.

| 비교 대상 | 입력·방식 | 확인 목적 |
|---|---|---|
| 단순 기준 | 다음 시즌 타율 = 현재 시즌 타율 | 최소한의 비교 기준 |
| 기본 모형 | 현재 타율, 직전 3년 타율, 연령, log(PA), K%·BB%·HR%, 현재 리그 타율 | 기존 성적 정보로 가능한 예측 |
| 확장 모형 | 기본 모형 입력 + `babip_gap_t` | 개인 기준 대비 BABIP 차이의 추가 유용성 |

## 6.3. 결과 검증

자료를 무작위로 섞지 않고 **현재 시즌의 연도 순서**로 나눈다.

| 구간 | 현재 시즌 → 결과 시즌 | 현재 확보 자료의 평가 가능 건수 |
|---|---|---:|
| 학습 | 2015~2021 → 2016~2022 | 424 |
| 검증 | 2022 → 2023 | 59 |
| 최종 평가 | 2023~2024 → 2024~2025 | 114 |

모형 계수와 표준화는 학습 자료로 정하고, 릿지의 규제 강도는 검증 자료에서 선택한다. 선택이 끝나면 설계를 고정하여 최종 평가 자료에 한 번 적용한다. 두 모형은 같은 선수·시즌 자료에서 MAE를 비교하고, 최종 평가 두 시즌의 결과도 각각 보고한다. 예를 들어 MAE 0.020은 평균적으로 타율 2푼 정도의 오차라는 뜻이다.

동일 선수가 여러 시즌 등장하므로 선수 단위로 묶어 재표집하는 부트스트랩으로 모형 간 오차 차이의 불확실성을 확인한다. 선수 이름이나 ID를 모형 입력으로 사용하지 않는다. 추가로 타석 기준을 100·300으로 바꾸거나 SF를 ±1 조정했을 때 방향이 유지되는지 점검한다.

부상, 타구 속도·각도, 구장, 상대 수비를 충분히 통제할 수 없고 평가 표본도 제한되어 있다. 따라서 인과관계나 개별 선수의 확실한 반등을 주장하지 않으며, 성능 차이가 작거나 불확실성 구간이 넓으면 활용 가능성이 제한적이라고 판단한다.

# 7. 생성형 AI 활용 계획

| 활용 단계 | AI 활용 내용 | 직접 검증 방법 |
|---|---|---|
| 질문·자료 탐색 | 분석 질문 구체화, 후보 데이터와 공식 지표 정의 탐색 | 출처 페이지·라이선스·실제 CSV 확인 |
| 전처리 | pandas 코드 작성, 과거 기록 및 다음 시즌 연결 코드 검토 | 표본 선수를 손으로 계산하고 미래 기록이 입력에 섞이지 않는지 확인 |
| EDA·시각화 | 분포·산점도·선수별 추이 그래프 코드 작성 | 그래프의 값·축·그룹별 건수를 원자료와 대조 |
| 분석·오류 해결 | 회귀 코드, 시간순 검증, 코드 오류 해결 지원 | Notebook을 직접 실행하고 기본·확장 모형의 동일 평가 조건 확인 |
| 해석·보고서 | 결과 해석의 논리와 문장 검토 | 출력 수치·불확실성·데이터 한계에 근거해 작성 |

ChatGPT 또는 Copilot 등을 활용하되, AI가 만든 데이터·수치·예시를 실제 결과로 사용하지 않는다. 핵심 질문, 변수 정의, 분석 선택에 사용한 프롬프트와 검증 내용을 Notebook 또는 별도 기록에 남긴다. 반등 사례뿐 아니라 반등하지 않은 사례와 가설을 지지하지 않는 결과도 제시한다.

# 8. 향후 진행 계획

| 단계 | 예상 기간 | 수행 내용·결과물 |
|---|---|---|
| 자료 확보·설계 | 1주차 | 버전 고정 다운로드, 구조 확인, 계획서 작성. 현재는 이 단계까지 진행 |
| 품질 점검·전처리 | 2주차 | 공식 기록 일부 대조, 파생 변수 생성, 다음 시즌 연결 및 탈락 내역 정리 |
| EDA | 3주차 | 시즌별·개인별 분포, BABIP 차이와 회복 폭 시각화 |
| 본 분석 | 4~5주차 | 기본·확장 회귀 모형, 검증 자료에서 분석 선택 확정 |
| 결과 검증 | 6주차 | 최종 시간순 평가, 선수 단위 불확실성·표본 기준·SF 민감도 확인 |
| 결과 전달 | 7주차 | Streamlit에서 선수·시즌 선택, 기준선·실제 기록·다음 시즌 변화 표시 |
| 최종 정리 | 8주차 | 실행 가능한 Notebook, 분석 보고서, README·실행 방법 작성 |

진행 흐름은 **데이터 확보 → 품질 확인 → 전처리 → EDA → 회귀분석 → 결과 검증 → 시각화·인사이트 → 최종 보고서**이다. 일정은 수업의 실제 최종 제출 기한에 맞춰 조정한다.

최종 Streamlit 화면에는 선수별 추이와 과거 사례를 표시하고, 표본이 부족하면 그 사실을 함께 보여준다. 개발 일정이 부족해도 Notebook과 보고서에서 세 가지 질문에 대한 검증을 완료하는 것을 우선한다. 1차 제출에서는 분석 결과나 모델 성능을 완성했다고 주장하지 않고, 질문과 자료 확보 가능성 및 검증 설계를 제시한다.

프로젝트 파일은 다음 구조로 관리한다. 원본 CSV는 로컬에서 보관하며 Git 추적에서 제외한다.
